# earth, lately. — 파이널 발표문

시연을 포함해 약 4~5분 분량입니다. 괄호 안의 문장은 화면 조작 안내이며 읽지 않아도 됩니다.

안녕하세요. 제 프로젝트 제목은 ‘earth, lately.’입니다. ‘요즘 지구는 어떤 표정을 짓고 있을까?’라는 질문에서 시작했습니다.

기후 관련 수치는 자주 접하지만, 숫자만으로는 그 상태를 직관적으로 느끼기 어렵다고 생각했습니다. 그래서 외부 데이터를 지구 캐릭터의 색과 표정, 움직임으로 바꾸는 웹사이트를 만들었습니다. 이 프로젝트에서 데이터를 보내는 쪽은 외부 데이터 서비스이고, 받는 쪽은 브라우저와 그 안의 지구 캐릭터입니다.

화면을 보시면 지구 주변의 색, 눈물, 머리의 흔들림, 눈의 피로도가 함께 나타납니다. 기준 평균보다 높은 전 지구 온도 차이는 노랑에서 주황, 빨강으로 이어지는 열기 표현에 사용했습니다. 반대로 평균보다 낮으면 차갑게 얼어가는 표현이 나타납니다. 여러 지점에서 받은 강수량 추정치와 전 지구 해수면 관측값은 눈물에 반영했습니다. 지진은 직전 한 시간보다 발생 횟수가 늘었을 때 머리 흔들림으로 표현했습니다. 지진은 기후위기의 결과라는 뜻이 아니라, 별도의 지질 데이터로 구분했습니다.

이 작업에는 수업에서 배운 코드를 크게 다섯 가지 방식으로 적용했습니다.

첫 번째는 Week 10의 ISS 예제에서 배운 API 요청 방식입니다. 수업에서는 `fetch()`로 ISS 위치를 받고, `response.json()`으로 위도와 경도를 읽었습니다. 여기서는 같은 흐름으로 선택한 위치의 날씨와 대기질을 받습니다. `async`와 `await`로 응답을 기다리고, 응답 객체에서 기온, 강수량, AQI처럼 필요한 값만 꺼내 사용합니다. 전 지구 온도와 해수면은 NASA 자료를, 지진은 USGS 데이터를 사용했습니다.

(지구를 돌린 후 육지의 한 지점을 더블클릭합니다.)

이렇게 지구를 더블클릭하면 선택한 지점의 위도와 경도로 데이터를 요청합니다. 국가와 지역 이름도 좌표를 이용해 조회합니다. 수업에서 좌표를 화면의 위치로 연결했던 방식을, 사용자가 고른 위치의 정보를 가져오는 방향으로 확장했습니다. 지구의 3D 표현과 표면 좌표 선택에는 추가로 Three.js 라이브러리를 활용했습니다.

두 번째는 Week 3에서 배운 조건문과 함수입니다. 수업에서는 온도에 따라 배경색을 바꾸는 예제가 있었는데, 저는 그 조건의 결과를 지구의 색과 표정으로 확장했습니다.

예를 들어 대기질을 표현하는 `getAirMood()` 함수는 AQI를 받아 눈의 피로도와 짧은 설명을 정합니다. AQI가 50 이하면 추가적인 피로 표현이 없고, 그보다 높아지면 단계적으로 눈이 무거워집니다. 같은 함수를 설명 문구와 실제 눈의 움직임에 연결해서 두 표현이 같은 데이터를 따르게 했습니다. 이 단계는 데이터를 감정으로 번역하기 위해 정한 디자인 규칙입니다.

(Air를 눌러 도시를 검색하고 결과를 선택합니다.)

세 번째는 Week 6에서 배운 `addEventListener()`입니다. 검색 제출, 저장 버튼, 더블클릭, 말풍선 클릭을 각각 이벤트에 연결했습니다. 사용자는 지구를 돌려볼 수도 있고, 장소를 선택해 데이터를 요청할 수도 있습니다. 바다를 선택하면 바다에 맞는 말풍선이 나오도록 했습니다. 이때 해수면 수치는 그 지점의 실시간 수위가 아니라 전 지구 평균 관측값입니다.

네 번째는 DOM을 바꾸는 코드입니다. `createElement()`로 검색 결과와 저장한 장소 버튼을 만들고, `textContent`로 지역명과 수치를 넣은 뒤 `append()`로 목록에 추가합니다. 미리 모든 지역의 화면을 만들어두는 대신, API 결과와 저장된 배열에 맞춰 화면을 구성했습니다.

(육지나 도시에서 Save를 누르고 페이지를 새로고침합니다.)

다섯 번째는 Week 11의 단어 목록 저장 예제입니다. 수업에서는 단어를 배열에 추가하고 `localStorage`에 저장했습니다. 저는 단어 대신 도시와 선택한 지점을 저장했습니다. `push()`로 추가하고, `filter()`로 삭제하고, `forEach()`로 저장 목록을 다시 화면에 만듭니다. 배열은 `JSON.stringify()`로 문자열로 바꿔 저장하고, 다시 방문하면 `JSON.parse()`로 복원합니다. 저장하는 것은 장소 선택이며, 날씨 수치는 API에서 다시 받습니다.

또한 ISS 예제의 `setInterval()`을 응용해 데이터를 주기적으로 확인합니다. 다만 모든 데이터가 초 단위로 바뀌는 것은 아닙니다. 날씨와 대기질, 월별 온도와 해수면은 갱신 주기가 다르기 때문에 각각의 데이터 시각을 표시했습니다. 오래되거나 받을 수 없는 지역 데이터는 임의의 값으로 채우지 않고 사용할 수 없다고 안내합니다.

디자인에서는 사용자가 캐릭터와 데이터의 관계를 바로 이해하도록 정보량을 줄였습니다. 화면에는 실제 수치, 출처, 데이터 시각과 짧은 표정 설명을 남겼습니다. 도시 선택은 지역 대기질에 따른 눈 표정에 반영되고, 전 지구 온도나 해수면 자료는 별도로 유지됩니다.

제가 이 프로젝트를 통해 보여주고 싶었던 것은 데이터를 감정적으로 읽는 경험입니다. 수업에서 배운 API 요청, 조건문, 이벤트, DOM 조작, 배열과 저장 기능을 연결해, 사용자의 선택에 반응하는 지구의 얼굴로 만들었습니다. 감사합니다.

발표 시 두 도시의 데이터가 비슷하면 표정 변화도 작을 수 있습니다. 억지로 다른 결과를 보이기보다 현재 수치와 조건을 함께 설명하면 됩니다. 3D 라이브러리, 역지오코딩과 지도 판별은 수업의 기본 코드를 확장한 부분으로 구분해 설명하세요.
